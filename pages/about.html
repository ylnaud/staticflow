Cómo funciona StaticFlow

Un generador de sitios estáticos mínimo: tomás páginas HTML, usás componentes reutilizables, y obtenés un sitio listo para subir.

El flujo completo

Cuando ejecutás npm run build, StaticFlow hace tres cosas:

  • Lee los archivos en _components/ y los resuelve (incluyendo imports anidados)
  • Compila cada página en pages/, reemplazando los <!-- @import nombre --> con el contenido del componente
  • Copia los assets de assets/ y genera todo en public/

Componentes

Creá cualquier archivo .html en _components/ e importalo desde tus páginas:

<!-- _components/header.html -->
<header>
  <a href="/">Mi Sitio</a>
</header>

<!-- pages/index.html -->
<!-- @import header -->

Los componentes pueden importar otros componentes. Si hay un ciclo de imports (A → B → A), el build falla con un error claro.

Rutas

Usá rutas absolutas en tu HTML (href="/assets/css/styles.css") y StaticFlow las convierte automáticamente en rutas relativas según la profundidad de cada página.

Comandos disponibles

ComandoDescripción
npm startModo desarrollo: build + servidor en localhost:3000 + watch
npm run buildBuild de producción con minificación (HTML, CSS, JS)
node staticflow.js --port=8080Cambiar el puerto del servidor de desarrollo
node staticflow.js --quietModo silencioso (menos mensajes en consola)

Despliegue en Vercel

El repo ya incluye un vercel.json configurado. Para desplegarlo:

  • Importá el repo desde vercel.com/new
  • Vercel detecta el build command (npm run build) y la carpeta de salida (public/) automáticamente
  • Cada push a main dispara un redeploy

Limitaciones conocidas

  • Las rutas absolutas dentro de CSS (url(), @import de CSS) no se reescriben — usá rutas relativas en tus archivos CSS
  • El minificador de JS es básico (regex) — funciona para scripts simples pero puede tener problemas con template literals o sintaxis compleja
  • No hay soporte para variables de entorno ni preprocesadores (Sass, TypeScript, etc.)
