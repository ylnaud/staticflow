Documentación

StaticFlow

Generador de sitios estáticos sin dependencias externas. Tomás páginas HTML, usás componentes reutilizables, y obtenés un sitio listo para subir a cualquier hosting.

Instalación

Necesitás Node.js ≥ 22.15.0. No hay npm install — el motor no tiene dependencias externas.

  1. Cloná el repo como plantilla

    Hacé clic en "Use this template" en GitHub o usá el link directo:

    # Clonar directamente
git clone https://github.com/ylnaud/staticflow mi-sitio
cd mi-sitio
  2. Iniciá el servidor de desarrollo 
    npm start
# → servidor en http://localhost:3000 con live reload
  3. Editá las páginas

    Modificá los archivos en pages/ y _components/. El servidor reconstruye automáticamente ante cada cambio.

  4. Build de producción 
    npm run build
# → genera public/ con HTML, CSS y JS minificados

Componentes

Cualquier archivo .html en _components/ se puede importar con:

<!-- @import nombreDelComponente -->

StaticFlow reemplaza ese comentario con el contenido del archivo _components/nombreDelComponente.html antes de generar la página.

Imports anidados

Los componentes pueden importar otros componentes. Por ejemplo, header.html puede importar un componente logo.html:

<!-- _components/header.html -->
<header>
  <!-- @import logo -->
  <nav>...</nav>
</header>

Detección de ciclos

Si dos componentes se importan mutuamente (A → B → A), el build falla inmediatamente con un error claro:

❌ Error: Importación circular detectada: header -> logo -> header

Componente inexistente

Referenciar un componente que no existe rompe el build con exit code 1:

❌ Error: Componente "navbar" no encontrado

Rutas

Usá rutas absolutas en tu HTML. StaticFlow las convierte automáticamente en rutas relativas según la profundidad de cada página:

<!-- En tu HTML usás rutas absolutas -->
<link rel="stylesheet" href="/assets/css/styles.css">
<a href="/">Inicio</a>

<!-- Para pages/blog/post.html StaticFlow las convierte a -->
<link rel="stylesheet" href="../../assets/css/styles.css">
<a href="../../">Inicio</a>

Minificación

npm run build activa --minify y procesa HTML, CSS y JS. El modo desarrollo (npm start) no minifica para facilitar el debugging.

El minificador es basado en regex — no es un parser completo. Funciona bien para la mayoría de los casos:

TipoQué haceLimitación
HTML Elimina comentarios, colapsa espacios entre tags No toca el contenido de <pre>
CSS Elimina comentarios y espacios innecesarios No soporta @import de CSS externo
JS Elimina comentarios, colapsa espacios Puede fallar con template literals complejos

Config file

Creá un archivo staticflow.config.js en la raíz del proyecto para configurar el motor sin tocar argumentos de CLI:

// staticflow.config.js
module.exports = {
  port:    3000,
  verbose: true,
  minify:  false,
};

La precedencia es: defaults ← config file ← args de CLI. Un argumento de CLI siempre gana.

OpciónTipoDefaultDescripción
portnumber3000Puerto del servidor de desarrollo
verbosebooleantrueMostrar mensajes en consola
minifybooleanfalseMinificar HTML, CSS y JS
componentsstring'_components'Carpeta de componentes
pagesstring'pages'Carpeta de páginas fuente
outputstring'public'Carpeta de salida del build
assetsstring'assets'Carpeta de assets estáticos

Comandos

ComandoDescripción
npm startBuild + servidor en localhost:3000 + watch de cambios
npm run buildBuild de producción con minificación, genera public/
node staticflow.js --port=8080Cambiar el puerto del servidor
node staticflow.js --quietSuprimir mensajes de consola
node staticflow.js --minifyActivar minificación explícitamente

Despliegue

Vercel

El repo incluye vercel.json preconfigurado. Para desplegarlo:

  1. Importá el repo desde vercel.com/new
  2. Vercel detecta el build command (npm run build) y la carpeta de salida (public/) automáticamente
  3. Cada push a main dispara un redeploy automático

Netlify

  1. Build command: npm run build
  2. Publish directory: public
  3. Node version: 22 (en Environment variables: NODE_VERSION=22)

Hosting estático genérico

Ejecutá npm run build y subí el contenido de la carpeta public/ a cualquier hosting que sirva archivos estáticos (GitHub Pages, Cloudflare Pages, S3, etc.).

Limitaciones conocidas

  • Las rutas dentro de CSS (url(), @import de CSS) no se reescriben — usá rutas relativas en tus archivos CSS.
  • El minificador de JS es basado en regex, no en un parser AST real. Puede tener problemas con template literals o regex literales con //.
  • No hay soporte para preprocesadores (Sass, TypeScript, PostCSS, etc.).
  • No hay sistema de variables ni datos dinámicos — todo es HTML puro.
  • El watcher usa fs.watch nativo, que en Linux puede requerir ajustar inotify para proyectos con muchos archivos.
